# Runbook: Approval Backlog（审批积压）

> 适用：等待审批的 Action/晋升请求大量堆积，Run 长时间停留在等待审批阶段，审批即将过期。
> 目标：积压可见、过期语义明确、高风险决策不被"过期放行"或批量盲批。

## 1. 检测

- /v1/approvals 待处理数量持续上升（运营操作中心审批区实时展示）。
- 审计事件 `approval.requested` 速率远高于决策事件速率。
- Run 状态分布中 `awaiting_approval` 占比异常。

## 2. 分诊（按风险等级）

1. **L2 可逆写**：可由具备 `approver` 角色的值班者按影响摘要逐条决策。
2. **L3+ 外部承诺 / 晋升审批**：必须由独立于 generator/grader 的审批者处理；
   值班者无权时升级到责任审批人，不得转授。
3. **Candidate 晋升**：审批必须携带理由（API 强制）；`awaiting_approval` 的 Candidate
   不会自动晋升或自动拒绝。

## 3. 过期语义

- 过期的审批请求视为"未授权"：Run 走拒绝/失败路径，**不是**默许放行。
- 积压清理的正确方式是决策（批准/拒绝）或让请求过期后由发起方在修正后重新提案，
   绝不批量 `approved=true`。

## 4. 高峰处置

1. 在运营操作中心逐条执行审批决策（输入 `APPROVE` 确认 + 理由，幂等键防重复）。
2. 若积压源于审批人缺失：走委托（delegation）临时授权给具备资格的替代审批者，
   委托可被即时撤销并留痕。
3. 若积压源于系统误报高频审批：检查工具的风险等级配置与 OPA 策略版本，修正后
   在变更审批中说明（不得直接改历史审计）。

## 5. 复盘指标

- 积压峰值与持续时间；中位审批时延（APPROVAL_LATENCY SLI，需事件配对仪表）。
- 过期占比与拒绝占比；因积压导致的 Goal 超时数量。
