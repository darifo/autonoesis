# Domain Model

> Status: baseline · Last reviewed: 2026-08-09 · Applicable version: 0.1.0

## 1. Object Relationship Map

```text
Tenant → GoalContract
Actor / Principal / AgentIdentity → GoalContract
SubjectRef → GoalContract
Session -. "initiates or observes" .-> GoalContract
GoalContract → Run
Run → ContextSnapshot
Run → Plan Version
Plan → Task DAG
Task → DecisionRecord
Task → Action
Action → Approval
Action → Artifact / Tool Result
Action → Evidence
Evidence → Outcome
Outcome → Evaluation Trial
Evaluation Trial → ImprovementProposal
ImprovementProposal → CandidateVersion
CandidateVersion → Release / Rollback
```

## 2. Core Object Definitions

| Object | Semantics | Minimum Required Fields |
|---|---|---|
| `SubjectRef` | Stable reference to an external authoritative business object | `system`, `type`, `id`, `version` |
| `GoalContract` | A manageable, verifiable goal contract | `goal_type`, `statement`, `desired_outcome`, `subjects`, `criteria`, `constraints`, `owner`, `risk`, `budget`, `deadline` |
| `Session` | Interaction continuity—not execution lifecycle | `actor`, `channel`, `goal_refs`, `status` |
| `Run` | An independently auditable, recoverable execution | `goal_id`, `agent_version`, `status`, `budget_snapshot`, timestamps |
| `Plan` | Versioned Task DAG with assumptions | `run_id`, `version`, `tasks`, `assumptions`, `created_by` |
| `Task` | A schedulable work unit with no external side-effect semantics | `dependencies`, `completion_criterion`, `assigned_capability`, `status` |
| `DecisionRecord` | Why something was executed, rejected, escalated, or re-planned | `decision`, `rationale`, `facts`, `policy_version`, `actor/principal/agent` |
| `Action` | The smallest governable side-effect boundary | `tool`, `operation`, `resource`, `parameters`, `risk`, `idempotency_key`, `expected_effect` |
| `Artifact` | Content or file generated by execution | `digest`, `media_type`, `storage_ref`, `classification`, `provenance` |
| `Evidence` | A citable observation of real-world state | `source`, `reference`, `observed_state`, `captured_at`, `integrity` |
| `Outcome` | Whether a success criterion was met in reality | `criterion`, `status`, `evidence_refs` |
| `Evaluation Trial` | A single evaluation of a versioned subject under fixed conditions | `subject_version`, `case`, `harness`, `transcript`, `outcome`, `grader_results` |
| `CandidateVersion` | A new capability version before production release gates | `baseline`, `artifact`, `generator`, `suite`, `status` |

## 3. Single Writer Matrix

| Object | Authoritative Writer | NOT an Authoritative Source |
|---|---|---|
| Goal / Run / Action / Approval / Outcome | Application Use Case (Core PostgreSQL) | Models, Temporal Search Attributes, Traces |
| Workflow History, Timer, Signal, Retry | Durable Workflow Engine | Database projections, Queue messages |
| External Business Entities | Corresponding CRM/ERP/ITSM/Business System | Agent DB, Vector Store, Memory |
| Evidence Payload | Immutable Object Store | Temporary Workspace, Model summaries |
| Knowledge | Enterprise-designated knowledge sources | Retrieval ranking, LLM rewrites |
| Memory | Memory Ledger via Memory Write Gate | Single run output, derived representations |
| Policy / Delegation | IAM / Policy Administration Point | Agent Prompt, Tool Description |
| Stable Capability | Release Service | Improvement Generator, single Grader |

## 4. State Machine Baseline

### Goal

```
Draft → Active | Cancelled
Active → Paused | Satisfied | Failed | Cancelled
Paused → Active | Failed | Cancelled
```

### Run

```
Pending → Running | Cancelled
Running → Blocked | AwaitingEvidence | Succeeded | Failed | Cancelled
Blocked → Running | Failed | Cancelled
AwaitingEvidence → Succeeded | Failed | Cancelled
```

### Task

```
Pending → Ready | Blocked
Ready → Running | Blocked
Running → Blocked | Succeeded | Failed
Blocked → Ready | Failed
```

### Action

```
Proposed → AwaitingApproval | Authorized | Denied
AwaitingApproval → Authorized | Denied
Authorized → Executing
Executing → Succeeded | Failed | Unknown
Unknown → Succeeded | Failed
```

### Candidate

```
Draft → Evaluating | Rejected
Evaluating → AwaitingApproval | Rejected
AwaitingApproval → Approved | Rejected
Approved → Stable
Stable → RolledBack
```

All state transitions must be explicitly defined in the domain layer and executed transactionally by Application Use Cases with event publication. Controllers, ORM hooks, Workflow scripts, or models must not freely write state.

## 5. Goal Clarification & Planning

### Uncertainty Decomposition

Sparse input must not produce a single vague "confidence score." The platform decomposes uncertainty into: intent, scope, fact, causality, capability, outcome verifiability, and risk uncertainty.

### Clarification Rules

```text
Parse Intent
  → Distinguish known facts, assumptions, preferences, and constraints
  → Evaluate sensitivity of missing information to success and risk
  → Low risk and reversible: proceed with explicitly recorded assumptions
  → Affects scope, permissions, amounts, irreversible outcomes: clarify with human
  → Cannot verify success criteria: do not start autonomous execution
  → Form versioned GoalContract
```

### Replan Triggers

Must trigger Replan when: critical Environment Fact expires or changes, predecessor Task fails, budget/deadline is exceeded, policy changes, approval modifies executable scope, new Evidence negates key assumptions, external object version conflict, or predefined quality/risk threshold is measured.

## 6. `EvaluationCase` vs. Business `Case`

`EvaluationCase` is a reproducible evaluation sample. It is unrelated to the optional business `Case` aggregation. Code naming and documentation must not conflate the two.

## 7. Implementation Status

All core domain objects are implemented as frozen dataclasses in `packages/domain/src/autonoesis_domain/`:

- `goals.py` — GoalContract, SubjectRef, SuccessCriterion, Session, Run

- `assets.py` — AgentDefinition, AgentVersion, SkillDefinition, ToolDefinition, LoopPolicy
- `context.py` — ContextSnapshot, EnvironmentFact, KnowledgeRef, MemoryRecord
- `evaluation.py` — EvaluationCase, EvaluationSuite, Trial, GraderResult
- `improvement.py` — ImprovementProposal, CandidateVersion, Release
- `transitions.py` — InvalidStateTransition, require_transition
