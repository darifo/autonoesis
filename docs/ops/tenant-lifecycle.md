# 租户生命周期流程（P2-05）

所有动作经平台 API 以审计身份执行，进入哈希审计链；这里定义的是流程与责任。

## 开通（Onboarding）
1. 供应租户记录（provision 工具/API），生成 `TenantNamespaces` 全量物理命名空间
   （对象前缀/缓存键/搜索/向量/主题/Temporal 命名空间/遥测/评估数据集/审计导出）。
2. 角色初始化：tenant_admin 首人 + 审批人/操作者/评估者分离的最小集合。
3. 能力安装：仅经签名供应链（允许列表+ed25519+SBOM）；按需设置 Stable Channel。
4. 验收：双租户攻击矩阵在隔离环境重放通过后放行。

## 升级（Platform Upgrades）
- 数据库：Alembic 前滚，禁止手改；回滚 = 恢复演练流程（PITR/备份集）。
- Pack：Channel 指针切换（依赖复核内建）；撤销不可逆。
- 平台版本：滚动升级（maxUnavailable=0），变更走下述变更审批。

## 暂停 / 恢复
- 暂停 = 租户级 Kill Switch（HALT + 理由）；Run 停在可恢复状态。
- 恢复 = RESUME（解除理由，二线批准），Temporal Run 从历史继续，不重复副作用。

## 数据导出 / 删除（数据主体请求）
- 导出：按租户命名空间的对象前缀 + 数据库行（RLS 限定），附审计引用。
- 删除：走证据删除流程（墓碑+证明），Memory 递归传播与向量投影清理已在组件
  测试验证；审计链不可删除（合规保留）。

## 退出（Offboarding）
1. Kill Switch → 2) 导出确认 → 3) 数据删除（含对象存储版本与向量/搜索投影）→
4) 撤销全部 Pack 与 Channel → 5) 租户记录归档（审计链保留期由合规策略决定）。
